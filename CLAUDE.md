# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Source of 艾伦's personal website, served at https://ztboxs.github.io. It is a single-page Vite + React 19 + TypeScript app in Simplified Chinese, aimed at startup founders, potential partners and hiring managers. The old Hexo blog output that used to live here was removed on 2026-10-21 and only survives in git history.

## Commands

- `npm run dev` starts the dev server.
- `npm run build` typechecks (`tsc -b`) and builds into `dist/`.
- `npm run lint` runs ESLint. `npm run format` runs Prettier (with the Tailwind class sorter).
- `npx shadcn@latest add <component>` adds a shadcn/ui component into `src/components/ui/`.

There are no tests yet.

## Deployment

`.github/workflows/deploy.yml` lints, builds and publishes `dist/` to GitHub Pages on every push to `master`. The repo's Pages source must be set to "GitHub Actions" (Settings, Pages). Do not commit `dist/`. Never publish or push on the owner's behalf without being asked.

## Design concept: 艾伦的移动城堡

The site is themed on Studio Ghibli's Howl's Moving Castle through painted fan art of the film's objects. Do not use film stills as backgrounds or banners in the sections: the owner rejected that look (it reads as anime wallpaper). Decorate the content with small illustrations instead. The hero's painted landscape backdrop is the one exception the owner approved. Keep the credits block in the footer (`credits` in `src/content/art.ts`).

The site has two modes (`mode` in `src/stores/world-store.ts`). With WebGL2 and no reduced motion it opens on the island; otherwise, or after "阅读模式", it shows the reading page described below.

- **Island (free exploration)**: `src/components/explore/explore-view.tsx` lazy-loads `src/components/world/world-scene.tsx`, a cel-shaded island the visitor orbits freely (drei `CameraControls` in `camera-rig.tsx`). Each door is a place with a lantern hotspot (`hotspots.tsx`, cameras in `places.ts`): harbour 港口, meadow 原野, lookout 星夜 (turns the island to night), and the walking castle itself for 炉火. Choosing one flies the camera there and opens `PlacePanel`, which renders that door's section components (side panel on wide screens, bottom sheet on phones). Shared paint lives in `toon.ts` (`paintedToon`) and `parts.tsx` (`paint`); hand-written shaders read the shared `night` and `tint` uniforms from `daylight.tsx`. Postprocessing is `@react-three/postprocessing`.
- **Walking castle**: the body is `public/models/castle-body.glb`, a Hunyuan3D 2.1 model generated from the castle painting (shape only), thin invented plates removed, each crease-separated part painted with the nearest island palette colour, meshopt-compressed. The legs, bobbing and chimney smoke are code in `castle.tsx`; retune `BODY_SCALE`, `BODY_LIFT`, `CHIMNEYS` and `LEGS` if the model changes. The generation scripts and steps are in `.asset-drafts/h3d/README.md` (local only).
- **Hero (3D, reading page)**: `src/components/scene/hero-scene.tsx` is a React Three Fiber scene, lazy-loaded so it never blocks first paint. The walking castle is a painted billboard (`/art/castle.webp`) that bobs and sways, standing in front of a painted alpine backdrop (`/art/landscape.webp`), among drei volumetric `Clouds` with chimney smoke and `Sparkles`. The camera follows the pointer and dollies forward on scroll. `StaticScene` in `hero.tsx` is the same composition as plain images, shown while loading, without WebGL and under reduced motion.
- **Doors**: the castle door's four-colour dial (`/art/door-dial.webp`) is the navigation. `doors` in `src/content/site.ts` maps each colour to a place and a section (港口→精选项目, 原野→其他经历, 炉火→关于我, 星夜→联系; the timeline shares 星夜). The dial image's quadrants are TL black, TR blue, BR red, BL green, and each door's `angle` must match. Clicking plays `DoorPortal`. Use `useDoorLink()` for any in-page section link.
- **Sections**: each heading carries its door tag, a brush underline in the door colour that draws itself, and one painted keepsake (`Section` with `ornament`, rendered by `Ornament`): sailboat for projects, wildflowers for explorations, teacup for about, straw hat for the timeline, falling star for contact. The letter on the contact card and Turnip Head in the footer use `Ornament` too. The page sky behind them runs from morning to night with scroll (`SkyBackdrop`); its stops are tuned so night falls just before the timeline. Timeline and contact are `.dark` scopes (add `text-foreground` with `.dark`, since colour is inherited from `body`).
- **Calcifer**: `Calcifer` (`/art/calcifer.webp`) flickers in the about section and leaps when a working method is hovered.
- **Type**: LXGW WenKai Screen for Chinese, IM Fell English (`font-fell`) for dates and small Latin flourishes.

### Art pipeline

- Illustrations (castle, Calcifer, dial, landscape, paper texture, and the ornaments in `public/ornaments/`) were generated by the Codex agent in Herdr tab 2 into `.asset-drafts/` (git-ignored). Only curated, converted copies go to `public/`. Ornaments share one style: light watercolour with fine ink lines, a single object, transparent background, no faces.
- Convert every image to WebP before committing (ornaments trimmed to their content and fitted to 400px, cut-outs keep alpha). Record new art in `src/content/art.ts` with its real pixel size.
- `public/textures/cloud.png` is drei's cloud sprite, vendored so the scene makes no runtime CDN request.

## Dependency rules

Prefer mature libraries, keep component source under our control, keep one design language, and never add a second library for a job an existing dependency already covers. Do not hand-write a component or behavior that an installed dependency can express correctly.

| Concern | Use | Notes |
| --- | --- | --- |
| UI components | shadcn/ui, `base-nova` style on Base UI (`components.json`) | Add via the shadcn CLI; the source lands in `src/components/ui/` and is ours to edit. Do not add Radix, MUI, etc. |
| Styling | Tailwind CSS v4 with the theme tokens in `src/index.css` | Merge classes with `cn` from `@/lib/utils`. |
| Icons | `lucide-react` only | Lucide v1 has no brand icons, so GitHub uses `FolderGit2Icon`. |
| Animation | `motion` (`motion/react`) | For CSS enter/exit on shadcn primitives, `tw-animate-css` is already in place. |
| State | `zustand` (`src/stores/site-store.ts`) | Active section, door transition state. Use the `persist` middleware for anything that should survive a reload. |
| 3D | `three` + `@react-three/fiber` + `@react-three/drei` (+ `@react-three/postprocessing`) | Keep scenes in `src/components/scene/` (reading hero) and `src/components/world/` (island) and lazy-load them. `package.json` `overrides` pins drei's `stats-gl` to our `three` so only one copy is installed; keep it when upgrading. |
| Layout panels | `react-resizable-panels` via `npx shadcn add resizable` | Not installed now; this is the one to use if panels are needed. |
| Drag and drop | `@dnd-kit/core` + `@dnd-kit/sortable` | Not installed now; this is the one to use if dragging is needed. |

## Layout of the source

- `src/content/site.ts` holds every word on the site plus media slots. Change content here, not in components.
- `src/components/sections/` has one component per section, in page order: hero, featured-projects, explorations, about, timeline, contact.
- `src/components/scene/` holds the 3D hero scene of the reading page.
- `src/components/world/` holds the island scene; `src/components/explore/` holds the HTML around it (top bar, intro card, dial, place panel).
- `src/components/magic/` holds the 2D effects (sky, dial, portal, Calcifer, stardust, falling stars, reveal).
- `src/content/art.ts` lists every image, its size, the film stills used per section, and the credits.
- `src/components/site/` holds the `Section` shell (scroll spy + heading) and `MediaFrame` (pinned photo / placeholder).
- `src/components/ui/` is shadcn-generated.

## Content rules (confirmed by the owner, do not loosen)

- Simplified Chinese, concrete and restrained. No unbacked claims ("行业领先", "商业闭环已验证" and the like).
- Never invent education, school, age, awards, clients, user counts, revenue, growth, funding amounts or team size. Never fill in months for year-only entries, and never extend open-ended dates ("起").
- Keep these states separate: code exists, tests pass, internal demo, partial external trial, public launch, commercial results.
- Keep personal contribution separate from team results. NomaCook's AI work was co-developed with a teammate. The companion company's seed round is a company milestone, not 艾伦's achievement, and must stay in its own block.
- The AI companion company stays anonymous everywhere (text, images, video, captions, file names, alt text, metadata). No real company or product name, logo, domain or client.
- No phone number, private repo links, internal URLs, credentials, logs or user data. No résumé download unless a confirmed file exists. No contact form without a real backend. No QR code for WeChat.
- Media without a real asset stays a visible `待补` placeholder naming the project, asset type and any anonymisation need. Never generate fake screenshots, testimonials, logos or numbers. Neon AI is text only. When a real asset is added, set `src` and drop the `待补` wording from its label.
- Do not write private background (looking for stable income, disputes at the previous company) into the site.
- Date ranges are written `2025.10 至 2026.07` (no dash characters in copy).
